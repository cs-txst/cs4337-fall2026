    Start with [2, 2]
    This is the pixel the appendix works through. Its gradient
      points almost straight down, so the two probes land above and below it, and both are
      larger. It loses, and it is set to zero.
    
    
    Then click [3, 2]
    One row down, on the ridge itself. Same near-vertical
      gradient, but now both probes are smaller. It survives at full value. That is the whole
      algorithm: a ridge is one pixel wide once you only keep its crest.
    
    
    A bug worth knowing about
    The notebook's
      bilinear_interpolation uses np.ceil(x)
      where it means floor(x) + 1. When a probe lands on an exact
      integer, which happens whenever the gradient is exactly horizontal or vertical, all four
      weights collapse to zero and it returns 0. That pixel then wins automatically.
      On the church photograph it inflates the edge count from 3,569 to 4,316. This page uses
      the corrected version.
    
    
    Push the distance
    At 2 pixels the probes reach past the ridge entirely and
      the survivor count doubles, from 5 to 10. More, not fewer. The comparison is only
      meaningful while the step stays inside the width of the edge.
