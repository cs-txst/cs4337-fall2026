Where the cost actually is
One slice of this accumulator holds 147,456 cells, which is nothing. Sweeping radius from 10 to 46 stacks 37 of them, 5.5 million cells, which is still fine. The problem is the voting: each of the 3,092 edge pixels has to paint a full circle of candidate centers at every radius, which is 20,125,828 increments for one 288 by 512 image.

    
What the gradient removes
That is the work the gradient trick removes, by replacing the whole circle of candidate centers with the two points that lie along the measured gradient, which would leave about 229,000.

    
What is computed here
This is the naive full-circle vote from the lecture pseudocode, recomputed in the browser so the radius can move, on cv.Canny(gray, 80, 160) of the coins image that ships with the course notebooks. The comparison button draws cv.HoughCircles(gray, cv.HOUGH_GRADIENT, dp=1, minDist=20, param1=160, param2=45, minRadius=12, maxRadius=45), which uses the gradient method and so does not build this accumulator at all. Expect its answers to be near these peaks, not identical to them.
