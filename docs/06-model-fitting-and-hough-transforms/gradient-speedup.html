What the tolerance saves
At ±90 degrees every pixel votes for all 180 thetas: 5,008,140 votes, top cell 290. At ±45 the work halves and the top cell drops to 289, so that saving is free. At ±20 it is 4.4 times less work for a top cell of 263, still a clear peak.

    
What it costs
Push to ±5 and the top cell falls to 118. At ±0, where each pixel votes only for the orientation Sobel measured, the work drops 180-fold and the top cell collapses to 14: the line is gone. A one-pixel gradient estimate is several degrees off, so a tight band makes the pixels of one real line miss each other's cells. The tolerance is not laziness, it is the allowance for that noise.

    
What is computed here
OpenCV's HoughLines has no gradient option, so this variant is computed in the browser. The orientations are not: they come from cv.Sobel with ksize 3 on the same road image, reduced modulo 180 degrees because a line has no direction sign, and one value is stored per edge pixel. The accumulator layout and the peak rule are OpenCV's.
