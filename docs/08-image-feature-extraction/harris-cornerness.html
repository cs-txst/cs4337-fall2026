Why a cloud and not a picture
Each point in the scatter is one pixel of the window, placed at its two gradient components. A flat patch puts every point at the origin. An edge stretches the cloud into a line, because the gradient always points the same way. A corner spreads it in both directions. The ellipse drawn over it is M, and its two axes are those two changes.

    
The parameter that bites
Raising k makes R more negative for edges, so fewer things count as corners. It does not make the detector more accurate, only stricter. Raising blockSize does something different: it enlarges the patch, so a corner that no longer fits inside the window starts to read as an edge. That is the scale failure, and no value of k repairs it.

    
Three scores, one idea
All three are functions of the same two changes, and all three are large only when both are. Harris and Stephens' R gets there from M's four entries directly, without ever working out what either change is, which is why it won in 1988 and why cv2.cornerHarris returns it. The smaller change on its own is what cv2.goodFeaturesToTrack uses by default.
