Shrink to See More

A stack of 3 × 3 convolutions that keeps the image at full size has two problems: each output value sees only a small window of the photo, and every layer is expensive. Build a stack here, add 2 × 2 pooling steps, and watch three numbers move together: how much of the photo one output value sees, how much computation the stack costs, and how coarse its output grid becomes.

Same size is not same view
With padding, every layer's output is as large as its input. The receptive field still grows, because a layer reads values that already summarize a neighborhood: one more pixel on each side per 3 × 3 layer, so 1 + 2L pixels after L layers. Ten layers see 21 pixels.

    
Pooling multiplies the step
After one pooling step, neighboring values are 2 pixels apart in the photo, so each later 3 × 3 layer adds 2 pixels per side, then 4, then 8. The same ten layers with five poolings see far more of the photo, at a small fraction of the cost.

    
The price is the grid
Five poolings turn 256 × 256 pixels into 8 × 8 answers. That is fine for "is there a person?" and useless for "which pixels?". A segmentation network pays this price in its encoder and buys the resolution back in its decoder.
